# PRISM — Tech Debt & Defects

Severity key: **P0** = gives silently wrong audit results · **P1** = crashes or broken features · **P2** = maintainability and UX · **P3** = cleanup.
Verified items are marked ✅. Those were reproduced in a quick script during the review. Everything else comes from reading the code.

**Tests.** Most items below are pinned by a test in `tests/` marked `@known_bug("<item>")`, which is a strict `xfail`. `pytest -ra` lists them all. When an item is fixed, its test starts passing and pytest fails the run, which means: delete the marker and keep the test as a regression guard. Find the tests for an item with `grep -rn 'known_bug("P0 #1")' tests`.

## P0 — Silent correctness errors (the audit numbers can be wrong)

For a bias-auditing tool these matter most. A wrong number that looks plausible does more damage than a crash.

### 1. Activations get scrambled across samples when a module runs more than once per forward pass ✅
**✔ Fixed in angle 3a.** The PyTorch inspector tags each captured call with its forward pass and its position in that pass. A module that runs k times per pass is stored as `name@0` … `name@<k-1>`, each pooled with the module's strategy, and analyses can use one call or `name@all` (the calls side by side). Per-item loops and chunked batches are joined correctly, and a model run more than once per item (e.g. test-time augmentation) is refused with a clear message instead of averaged. *Was:*
`core/execution.py:96-99` + `inspectors/pytorch.py:136-153`
If a hooked module fires *k* times per batch, the buffer holds `[call1: items 0..B-1, call2: items 0..B-1, …]`. Examples are a reused `nn.ReLU`, as in torchvision's `BasicBlock`/`Bottleneck` (used by the thesis ResNet-34), weight sharing, and RNN cells. The engine "fixes" the extra rows with `reshape(B, k, -1).mean(1)`, which groups **consecutive rows**. So "item 0" becomes the average of items 0 and 1 from the first call. The reshape also flattens the spatial dimensions *before* pooling, so the user's chosen strategy is skipped and the layer gets stored as `B × (C·H·W)`.
*Fix:* reshape to `(k, B, …)` and reduce over axis 0. Better still, keep only the last call, or let the user choose. Then pool.

### 2. Layers can end up misaligned with the metadata CSV
**✔ Fixed on `refactor/results-contract`.** Batches are written all-or-nothing through `CacheWriter`, and `AuditCache.open()` re-checks alignment. *Was:*
`core/execution.py:100-102, 134`
When one layer hits a shape mismatch, the engine runs `continue` and that layer's rows for the batch are never written. The batch's indices are still added to `successful_indices`. From then on that dataset is shorter than the CSV and shifted, and Probing and the Gallery pair activations with the wrong subjects. `__model_output__` is never shape-checked either.
*Fix:* fail the whole batch on any mismatch. Also write an `ids` dataset into the H5 and join on it, not on position.

### 3. Class-index → label mapping is guessed by string sort
**✔ Fixed on `refactor/results-contract`.** Connectors can declare `class_names` (and `output_kind`). The order is stored in the cache, and Performance and Gallery share one decoder (`core/labels.py`). Without a declaration, labels `0…k-1` map to themselves and anything else falls back to alphabetical order, with a visible `[NOTE]`. *Was:*
`gui/frames/performance.py:108,149,151` · `gui/frames/gallery.py:108-112`
Column *j* of the model output is taken to be `sorted(str(labels))[j]`. Suppose a model was trained with `CN=0, MCI=1, AD=2`. Sorting gives `AD, CN, MCI`, so every prediction gets relabelled and accuracy and the fairness gaps come out wrong with no warning. The binary 1-D path uses the same assumption (`> 0.5 → last sorted label`). The two tabs also disagree with each other: the Gallery's 1-D path emits `"0"/"1"` strings no matter what the labels are, so with labels like `"AD"/"CN"` every item shows up as an error.
*Fix:* make the connector declare `class_names` (and whether it outputs probabilities or logits), and store that in the H5 attributes.

### 4. `row_id` passed to the connector is the DataFrame index, not the ID column, and it changes between tabs
**✔ Fixed on `refactor/results-contract`.** `load_item` receives the ID-column value as a string, during extraction and in the Gallery alike. The ID column must exist and be unique. **This breaks connectors that relied on `row_id` being the row number.** *Was:*
`core/execution.py:59` passes `row.name` (the original index). `gallery.py:153,212` passes the index of the *filtered, re-indexed* cache CSV. When any row failed during extraction, the Gallery asks the connector for **a different item** than the one that was embedded. The configured `config_id_col` is never passed to the connector at all. The template's `row_id: str` annotation suggests the reverse.
*Fix:* pass `meta[config_id_col]` in both places.

### 5. The Keras hidden-layer extraction never runs ✅
`inspectors/keras.py:66`
`self.model.__call__ = hooked_call` assigns on the instance. Python looks up dunder methods on the **type**, so `model(x)` and `model.predict(...)` both go around it. The buffer stays empty and the H5 gets only `__model_output__`. The Wiretap tab still lists layers and the run reports `[SUCCESS]`.
*Fix:* call `feature_extractor` directly inside the engine, or wrap `predict` explicitly and document that.

### 6. The leakage screen misses the most important proxies and flags noise
*Follow-up found later:* the screen ignored Group By, so with several scans per subject the subject column (and any other subject-level code) scored as an EXTREME proxy for a per-subject label (verified: AUC 1.0 with 40 subjects x 12 visits). **✔ Fixed on `fix/correctness-bundle`.** The Group By column is excluded, the categorical scoring keeps each group in one fold, and the Evidence tab re-screens when the ID or Group By choice changes.

**✔ Fixed on `refactor/leakage-screen`.** One `analysis.confound_screen`, called by the Evidence tab. Continuous columns are scored on their raw values. Categorical columns are scored out-of-fold, so a small category can't vouch for itself, and categories with fewer than 10 rows are pooled. Missing values are their own category (or skipped for continuous columns), and multiclass targets use a one-vs-rest macro AUC. *Was:*
`gui/frames/evidence.py:151-164`
* Columns with ≥20 unique values are never checked. For an Alzheimer's classifier that means **MMSE, CDR-SB, ADAS, age** — the classic diagnosis proxies — are reported as `N/A`.
* "EXTREME" fires if *any single category* is more than 95% one class, so a category with one row always triggers it. On real data that produces many false alarms.
* `analysis.py:confound_screen` uses a different algorithm: a univariate logistic AUC on factorised codes, which treats categories as ordinal. It also drops any column that has a NaN (`len(encoded) != len(metadata)`) and fails on multiclass targets (`predict_proba[:,1]` into a binary AUC). The GUI and headless paths give different risk labels for the same CSV.

### 7. Probing statistics are biased
**✔ Fixed on `refactor/probe`.** `analysis.linear_probe` is now the one probe, and the Probing tab calls it. It splits folds with `StratifiedGroupKFold` when Group By is set, fits the scaler inside each fold, reports AUC and balanced accuracy against chance, and runs seeded shuffled-label controls (now 1–1,000, default 50) with a permutation p-value (shuffling whole subjects' labels when Group By is set). Missing labels are dropped rather than blocking the probe. The tab warns when Group By is unset, and the Gallery's lineup now skips the suspect's own group. *Was:*
`gui/frames/probing.py` · `analysis.py:linear_probe`
* `StandardScaler` is fit on the full matrix before CV, so test-fold statistics leak into training (`probing.py:174`).
* The score is plain accuracy compared against a `1/k` baseline. On imbalanced concepts (sex, scanner) the real chance level is the majority rate, so the probe looks stronger than it is. Use balanced accuracy or AUC.
* The control probe is a single unseeded permutation. It gives one noisy number, it isn't reproducible, and the warning threshold of `mean>0.6 and gap<0.10` is arbitrary.
* `analysis.linear_probe` **has no group support**. With ADNI's many scans per subject, its AUCs will be inflated by subject identity leaking across folds. That matters if the thesis tables come from this path, which the module docstring says they do.
* NaN labels become the string `"nan"` class during the class count, before the mask removes them (`probing.py:101-113`). So a **single** missing value makes the probe refuse to run ("Class 'nan' has too few samples"), even though dropping that row would leave a valid task. ✅ (pinned by a test)

### 8. Models are never forced into eval mode
**✔ Fixed on `fix/correctness-bundle`.** At the start of a run the PyTorch inspector puts every module in eval mode (with a warning if the connector left any in training mode) and runs inference under `torch.no_grad()`; teardown restores each module's original mode. *Was:*
Nothing calls `model.eval()` or `torch.no_grad()`. A connector that forgets either one gets dropout and BatchNorm in train mode, which makes embeddings nondeterministic and lets BN statistics drift. The vision example does it correctly, but the template doesn't say it is needed.

### 22. Rows that fail to load vanish from the audit without a trace ✅
**✔ Fixed on `fix/robustness`.** Every row that fails (in `load_item`, in `run_inference`, or because its batch's outputs don't fit) is recorded with where and why, and listed with its metadata in `prism_failed_rows.csv`; the results record how many rows were attempted and failed. The log, a warning when the run finishes, every analysis tab (the Gallery gained a notes line for it) and the top of the audit report say how many rows are missing and name the groups that lost noticeably more of their rows (`core/failures.py`), e.g. "site = B (all 30 rows: missing from every analysis)". Instead of asking mid-run, the run stops and saves nothing once more than a set share of all rows has failed: 5% by default, set in the Execution tab or as `max_failed_percent` in a job file, 100 to never stop. That works the same for cluster jobs, where nobody is there to ask. *Was:*
`core/execution.py` (`run_extraction`)
A row whose `load_item` raises, or a batch whose `run_inference` raises, is logged as a `[WARNING]` in the console and left out. The run still ends `[SUCCESS] Extracted 70/100 items`, the results open without a warning, and nothing records which rows were lost or why. Failures are rarely random: a scanner or site whose files have another format fails as a group. Verified with 100 rows where site B's 30 files are unreadable: the results hold site A only, and every fairness slice and probe by site sees one site.
*Fix:* record the attempted and failed rows (with reasons) in the results, show the count and the groups most affected in every analysis tab and the report, and ask before continuing when more than a few percent fail.

## P2 — Architecture and maintainability debt

1. **✔ Fixed on `refactor/audit-config`.** `core/config.py` (`AuditConfig`), `core/subject.py`, `core/dispatch.py` and `run_extraction(config, subject, metadata, …)`. The engine no longer touches Tk, and the headless mocks are gone. *Was:* **The GUI is the state store and the API.** `ExecutionEngine` reads the layer list and the pooling strategy by parsing `frame_wiretap.tree.item(i,"text")`. `headless.py` has to fake a Tk Treeview (`MockTree`/`MockWiretap`) to run. Execution also reads `frame_setup.ent_script` and `frame_evidence.ent_csv`. *Needed:* an `AuditConfig` dataclass (paths, columns, `layers: dict[name, strategy]`, batch size) that the GUI builds and the engine and headless runner consume.
2. **✔ Fixed on `4c/fairness`:** the Performance tab now calls `analysis.fairness_audit`, so every analysis tab runs on `analysis.py`. *Was:* **Two analysis implementations that disagree.** `analysis.py` (headless) and the GUI frames compute leakage, fairness, and probes with different algorithms, thresholds, and label handling. Nothing calls `analysis.py`. The GUI should call `analysis.py`, so there is one source of truth. A concrete case found while writing tests: the Performance tab counts a probability as positive when it is `> 0.5`, while `analysis.py` uses `>= 0.5`, so a score of exactly 0.5 is classified differently by the two paths. ✅ **✔ Fixed on `refactor/results-contract`.** The shared decoder uses `>= 0.5`, the same as `analysis.py`.
3. **✔ Fixed on `refactor/results-contract`.** See architecture.MD §3. *Was:* **No cache schema.** There are no IDs, no class names, no output semantics (probability vs logit), no strategy metadata, and no PRISM version in the H5. Filenames are hard-coded in 5 files.
4. **✔ Fixed on `angle6/packaging`.** Inspectors subclass `inspectors/base.py`'s `Inspector`; the registry lists the built-ins by import path and adds any declared in the `prism.inspectors` entry-point group (see architecture.MD §2). *Was:* **No plugin interface.** Inspectors are found by a class-name suffix and duck typing. Any class named `*Inspector` that gets imported into a plugin module will be registered. Failures are only `print`ed.
5. **✔ Fixed on `angle6/packaging`.** torch and TensorFlow are imported only by their plugins, on first use; the device label checks for torch in the background and only if it is installed. `requirements.txt` lists exactly what PRISM imports, frameworks are extras in `pyproject.toml`, and a test keeps imports and declarations in step. *Was:* **Hard torch dependency.** `app.py:60` and the inspector registry still import torch unconditionally, so a scikit-learn-only user must install PyTorch. TensorFlow is missing from `requirements.txt`, while unused heavy dependencies (wandb, catboost, xgboost, monai==1.5.2, nibabel) are listed.
6. **✔ Fixed on `angle6/packaging`.** Every import is `prism.*`; `pyproject.toml` makes PRISM installable (`pip install -e .`) with a `prism` command; only the run-as-a-file entry points and the user's project root touch `sys.path`. *Was:* **Import model.** `main.py` modifies `sys.path` so that `gui`, `core`, and `inspectors` resolve as top-level packages, `loader.py` keeps prepending user roots, and `connector_template.py` expects `prism.*`. Generic top-level names like `core` and `gui` can collide with the user's own packages. There is no `pyproject.toml`, so no `pip install -e .` and no console script.
7. **✔ Fixed on `angle5/worker`.** `gui/worker.py` (`Task`, `Runner`): work on a thread, messages through a queue drained by the Tk thread, cancellation through `core.cancel.Cancelled`; Cancel buttons on Execution and Probing, progress for ingestion, probes and the bootstrap. *Was:* **Threading.** Raw threads with ad-hoc `after()` calls. There is no worker/queue abstraction, no cancel button, and no progress for ingestion.
8. **Error handling.** Bare `except:` and `except Exception` with `print` in many places. No `logging`. `app.log` is just `print`.
9. *(Partly fixed on `4c/fairness`: every Performance figure and gap now has a 95% bootstrap interval that resamples whole subjects when Group By is set; groups below a minimum size (default 20) are shown but left out of the gaps; a gap above 0.15 is only a warning when its interval excludes 0; multiclass and regression targets can be sliced. Still open: the Gallery handles binary only, the "more than 10 unique values = regression" rule is still applied in each tab (now one shared constant), continuous slice columns such as age are not offered (no binning), and with many groups the largest gap is reported without a multiplicity correction, only a note.)* **Shortcuts in the analysis UX.** Multiclass slicing is "not supported in V1", the Gallery handles binary only, and task type is decided by a magic number ("numeric with more than 10 unique values = regression") repeated in 3 files. Fairness gaps are max−min with no CIs and no minimum group size; only accuracy gets error bars.
10. **No CI, no linting, no type checking.** A pytest suite now exists in `tests/` (509 tests, 94% line coverage of `prism/`). Nothing runs it automatically yet.
11. **✔ Fixed on `ux/wiretap-pooling`, as a usability item:** the code was never wrong, but the default's effect was invisible, and PRISM deliberately doesn't guess what a layer's axes mean (a 1-D CNN's `(B, C, L)` and a transformer's `(B, T, D)` have the same shape, and Mean Pool is right for one and wrong for the other). Show shapes in the Wiretap runs one row and shows each layer's output shape and what its pooling keeps; the info button lists what each strategy keeps; after the first batch the log says the same ("each row's output is 128×768; Mean Pool stores 128 values"), the results record each layer's shape, and the report lists it. Ticking a layer for extraction is now separate from selecting it, so layers can get different poolings without rebuilding the selection. *Was:* **The default pooling is ambiguous for sequence models.** The default "Mean Pool" assumes `(B, C, spatial…)`. On a transformer or RNN activation `(B, T, D)` it averages the *embedding* axis and stores one value per token. Anyone who doesn't right-click and choose Seq Pool / CLS Token gets a near-meaningless representation, with no warning. *(Angle 3a added Grid Pool, which keeps a coarse spatial layout for CNN maps.)*
12. **✔ Fixed on `4d/audit-report`** for the audit report: `prism/audit.py` corrects every probe's p-value across the report (Benjamini–Hochberg) and gives each probe enough shuffles for the correction to pass it, and says so when the user's shuffle count cannot. A test plants chance findings (noise probes at p < 0.05) and checks they are dropped. The Probing tab still shows one probe at a time, uncorrected. *Was:* **No multiple-comparison handling across probes.** Probing 10 layers × 5 concepts at p < 0.05 should produce a couple of "significant" results by chance alone, and nothing says so.
13. **(Low priority.)** **The logistic probe loads the whole layer.** Multinomial logistic regression (the non-default probe model) peaks at about 4.8× the layer's size in memory; fitting it blockwise would bring that to about 2.6×. The default LDA and ridge probes are streamed and unaffected.
14. **✔ Fixed on `feat/provenance`.** Each extraction records its PRISM, Python and package versions, the platform, when it started and finished, and SHA-256 fingerprints of the metadata CSV and connector script as the run started, plus a fingerprint of the model's weights as loaded (PyTorch: weights and buffers; scikit-learn: joblib's hash of the fitted estimator; Keras: its weights), so the model is covered wherever the connector found it. The run log shows the model fingerprint and the report ends with a Provenance section.
